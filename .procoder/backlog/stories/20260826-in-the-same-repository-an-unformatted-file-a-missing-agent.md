# House rules do not follow procoder into somebody else's repository

Status: done
Created: 2026-08-26
Epic: adoption-aware-gate
Sprint: 021-procoder-tells-third-party-repositories-only-what-is-true

## Description

The seventeen findings that should never have appeared. In a repository
that never adopted procoder, none of these run at all: the agent layer,
release and documentation hygiene, procoder's templates, the planning
chain, formatting, linting, maintainability, debt, and the suite.

Every one of them encodes a choice that repository did not make. Its
formatter is Biome, its changelog is generated by release-please, its
`AGENTS.md` is its own, and its test command is not procoder's business.

## Acceptance criteria

- [x] In a non-adopting repository, an unformatted file, a missing agent
      rule file, a README without the version, an absent linter, a debt
      marker and a failing suite produce no finding at all.
- [x] The domains are enumerated rather than sampled, so a domain added
      later and forgotten here fails the test rather than leaking into
      somebody else's repository.

## Evidence

`TestNoHouseRuleDomainSpeaksInANonAdoptingRepository` enumerates twelve
domain markers rather than counting findings, so a domain added later and
forgotten fails this test.

Scoping formatting meant moving the `config.Load`/`ScopeFor` pair above the
format loop in `RunWith` — the spec named formatting as a house rule but
never said where the code decides it, and four pre-existing fixtures
silently became non-adopting and had to declare `.procoder/`. Recorded in
#186.

Two criteria in this story cannot be observed on the fixture: the docs
domain needs a built index (it prints `public surface NOT computed` first)
and the suite leg needs a test suite. Both are green whatever the code
does. Also #186.
