Using it

Twelve commands

Every command is a Claude Code slash command in the procoder namespace, so they all read /procoder:<verb>. opencode and openclaw get the same twelve, ported from the same source files by scripts/sync-rules.js.

Control the gate

CommandWhat it does
/procoder:levelSet the intensity level: pragmatic, strict, paranoid — or off. Persisted across sessions.
/procoder:guardInstall procoder as a pre-commit hook and a CI check. It detects any hook manager and CI provider you already have and integrates with it rather than over it.
/procoder:statuslineInstall, inspect, or remove the statusline badge. It reports a statusline that is not procoder's rather than replacing it.
/procoder:updateUpdate an installed procoder, and name what the update invalidates — a changed baseline format, or a doctrine change that makes a copied rule file stale.
/procoder:helpThe rungs, the levels and the command list, in one screen.

Hunt for something

CommandWhat it does
/procoder:reviewReview the current diff against the four rungs. Takes an optional commit range or path.
/procoder:auditAudit the whole repository, ranked by rung severity. The deterministic engine runs over the scope before any judgment finding is formed.
/procoder:rotFind dead, stale, and deprecated code left behind — rung 4, run deliberately rather than as a side effect of a diff.
/procoder:threatMap every trust boundary and what validates it: each entry point, what an attacker controls there, and where the validation actually sits.
/procoder:depsAudit dependencies — vulnerable, abandoned, unpinned, unused — by running each ecosystem's own auditor, not a second opinion of its own.

/procoder:rot and /procoder:threat are the two with no equivalent in comparable tools: one hunts what previous changes left behind, the other maps where untrusted data enters and what stops it.

Measure

CommandWhat it does
/procoder:debtA ledger of every procoder: marker in the repository, classified as dated, undated or overdue, flagging any without a removal trigger.
/procoder:gainMeasured progress since a reference point: rot removed, boundaries hardened, baseline shrinkage. Every number comes from git or the baseline file, with the command that produced it.

The commands that report numbers are held to the same standard as this site: /procoder:gain is instructed to derive every figure from git or the baseline file and to show the command behind it, rather than estimating. A progress report that cannot be re-run is a marketing document.

Where they live

Each command is one file under commands/, and most of them invoke a skill of the same name that carries the actual method. The ports to .opencode/command/ and .openclaw/commands/ are generated from those files, and npm run sync:check fails the build if any port has drifted — so there is exactly one place to edit a command, and no copy that can quietly disagree with it.
