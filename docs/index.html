Claude Code plugin and CLI · v0.2.0 · Apache-2.0

procoder

An AI writes the change in seconds. What it rarely does is delete the thing the change replaced — so the old path survives, still exported, still called, still wrong.

procoder is the gate that refuses to call that done. Four rungs, checked in order, on every response and on every file the session touches.

  • [1 SAFE] api/users.ts:42 raw request role into authz check → validate + server-side role lookup
  • [2 TRUE] api/users.ts:58 error swallowed, write may be lost → propagate or log with correlation id
  • [3 OBVIOUS] api/users.ts:71 fn 94 lines, depth 5 → extract validate/persist/notify
  • [4 ALONE] api/users.ts:6 superseded export still there, no caller → delete it

That shape — rung, location, what is wrong, arrow, what to do — is every finding procoder emits. It is quoted from the doctrine, which is the single source the whole tool is generated from.

What it does

procoder runs in two halves that cover different ground. The doctrine is read by the agent and shapes what it writes: trust boundaries, error handling, naming, and whether the replaced path was deleted. The check engine is deterministic — regex and counters over six languages — and runs after every file write, plus on demand from the CLI.

The engine covers the smaller half, and the site says so wherever that matters. It pairs with the ponytail plugin: ponytail decides what to write, procoder decides whether it may ship.

Read the limits before you rely on it. The engine is heuristic, not a parser, and the things it is known to miss are written down and kept current rather than left for you to find: what it misses.

The four rungs

Every rung must hold before a change ships. They are checked in this order because the cost of getting one wrong descends — and the first two are not yours to trade away.

Not negotiable

  • [1 SAFE] Does untrusted data reach a sink unvalidated?
  • [2 TRUE] Are errors handled and edges covered, with one runnable check left behind?

Judgment

  • [3 OBVIOUS] Would the next reader get it in one pass?
  • [4 ALONE] Did you leave a twin behind?

Rung 4 is the rung nobody ships, and the reason procoder exists: a change isn't done until the thing it replaced is gone. Read the four rungs in full.

Install it

In Claude Code, two lines:

claude plugin marketplace add azrtydxb/procoder
claude plugin install procoder

For a pre-commit hook, a CI job, or a terminal with no agent in it, the same engine ships as a CLI: 

npm install -g procoder
procoder check <paths...>

Cursor, Windsurf, Cline, Kiro, Qoder, opencode, openclaw, Codex, Copilot, pi and any MCP host each read a rule file generated from that same doctrine. Get started has the path for each of them.
